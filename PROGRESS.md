### Как запустить сайт и посмотреть в браузере (пошагово)
1. Открыть VS Code с папкой `C:\apetit-site`.
2. Открыть терминал: меню **Terminal → New Terminal** (или `Ctrl` + `` ` ``).
3. Ввести `npm run dev` и нажать Enter. Через несколько секунд появится
   строка вида `- Local: http://localhost:3000`.
4. Открыть в браузере адрес **http://localhost:3000** — это и есть сайт.
   Внизу слева будет маленький кружок с буквой N — это служебный значок
   режима разработки, на настоящем сайте его не будет.
5. Остановить сайт: щёлкнуть в терминал и нажать `Ctrl` + `C`.

- `npm run build` — собрать сайт как для боевого сервера (проверка, что всё
  компилируется);
- `npm run lint` — проверка кода линтером;
- `npm test` — быстрые тесты; `npm run test:e2e` — тест в настоящем браузере
  (сам поднимает сайт и сам его гасит).

### CSP: почему без nonce

Проверил по документации Next 16 (в node_modules и через context7): nonce
работает **только если каждая страница собирается на сервере при каждом
заходе**. Тогда меню перестало бы быть готовым заранее (SPEC §9.5), каждый
заход считался бы на Cloudflare — медленнее и дороже. Поэтому рабочий вариант:
`script-src 'self' 'unsafe-inline'`. Встроенные скрипты разрешены (без них
Next не оживит статическую страницу), но **скрипты с любых других сайтов
запрещены**, данные уходят только на наш сервер, страницу нельзя встроить в
чужой сайт. `style-src 'unsafe-inline'` — анимации и размеры вывесок задаются
через атрибут style. `'unsafe-eval'` — только в режиме разработки (так требует
React). Экспериментальный SRI Next не решает проблему встроенных скриптов —
не включал.

По дороге нашёл: библиотека zod «на пробу» вызывает eval и получает запрет
CSP (в консоли — нарушение на меню и оформлении). Включил её официальный
режим без eval (`jitless`, файл `src/lib/zod.ts`; весь код теперь берёт zod
оттуда — это сторожит тест). Правила проверки заказа не изменились.

## 2026-09-21 — Этап 5 — движок анимаций (WebGL) и живой фон

### 1. Движок — `src/motion`

Архитектура в десяти строках:

1. `engine.ts` — одиночка на весь сайт: один `<canvas>` на весь экран (за
   контентом, клики проходят сквозь), один контекст WebGL2 (запас — WebGL1
   с `OES_standard_derivatives`; нет ни того, ни другого — движок молча
   выключен, сайт работает), один цикл кадров.
2. Эффект — это **слой**: `{ id, zIndex, init(gl), render(gl, frame), dispose(gl) }`.
   Слой сам владеет своими буферами, шейдерами и текстурами.
3. `engine.add(layer)` / `engine.remove(id)` — подключить и отключить.
4. Кадр даёт слоям `{ t, dt, width, height, dpr, scroll }`: `t` — секунды,
   `dt` — миллисекунды, `scroll` — общая сглаженная прокрутка.
5. `scroll.ts` — это сглаживание: `k = 1 − (1 − ease)^(dt/16.67)`,
   `smooth += (target − smooth) × k`. Слой сам умножает на свой `parallax`.
6. `quality.ts` — четыре уровня: 1) плотность до 1.5 · 2) плотность 1.0
   · 3) 30 кадров/с · 4) стоп. Первые две секунды движок считает кадры:
   меньше 50 — уровень ниже, ещё раз меньше 50 — ещё ниже, меньше 40 — стоп.
   Уровень живёт в sessionStorage и сам не повышается.
7. `pause.ts` — паузы по причинам. Цикл идёт, только когда причин нет.
   Встроены: спрятана вкладка, открыт лист блюда, открыта корзина, страница
   сама едет к категории. Причина — любая строка, будущая анимация бургера
   возьмёт свою.
8. «Уменьшить движение» — один кадр, цикл выключен, слои получают `t = 0`
   и `scroll = 0`. Потеря контекста — тихо уровень 4, без ошибок в консоли.
9. Движок подгружается **после показа страницы** (отдельный кусок кода,
   `ssr:false`), холст проявляется за 300 мс. На скорость первого экрана
   не влияет — цифры ниже.
10. Настройки всех эффектов — `src/config/motion.json` (читается при сборке),
    правятся в панели `/dev/motion`.

### 3. Схема (окончательная)

`src/config/alerts.json`:
```json
{ "reminderEvery": 2, "reminderMax": 15, "ownerAt": 12,
  "ownerRepeatEvery": 10, "ownerMax": 3 }
```

Отсчёт от времени заказа, две независимые дорожки:
- **точке** — `⏰ Comanda #1042 așteaptă — X minute` каждые 2 минуты, начиная
  с 2-й, максимум 15 раз (то есть 30 минут). X — сколько заказ уже ждёт;
  минуты склоняются правильно на обоих языках (`2 minute`, `20 de minute`,
  `21 минута`, `25 минут`);
- **владельцам** — `⚠️ Apetit Centru nu a preluat comanda #1042. Au trecut 12
  minute. Tel. punct: 067 578 757` на 12-й минуте, потом каждые 10 минут,
  всего 3 раза (12, 22, 32).

На 12-й и 22-й минуте дорожки совпадают — уходят оба сообщения. Тревог по три
сообщения 🚨 больше нет. Нажали «Am preluat» — всё прекращается мгновенно, на
любом шаге. Для Otaci — те же тексты по-русски.

**Потолки — главная защита**: когда обе дорожки пройдены (15 напоминаний и 3
сообщения владельцам), заказ выпадает из выборки самим запросом к базе и
больше не звонит никогда, даже если про него забыли.

  unit-тестами напрямую. База отдаёт кандидатов и **атомарно «забирает» шаг**
  условным UPDATE (счётчик поднимается, только если он ещё равен ожидаемому и
  заказ всё ещё `new`). Отсюда три свойства: параллельные запуски не
  продублируют сообщение; нажатие кнопки между выборкой и отправкой отменяет
  шаг; опоздавший на минуту cron шаг не теряет (условие «прошло ≥ N минут и
  шаг не выполнен», а не «ровно N»).
- Пауз внутри обработчика больше нет — запрос короткий, лимит Cloudflare
  Workers (30 с) недостижим.
- Копия заказа владельцу **не отправляется в чат самой точки**: если один чат
  записан в двух ролях (как у Амяна при проверке), раньше подряд приходили
  две одинаковые карточки — с кнопкой и без, и кассир видел внизу ту, что без
  кнопки. Это и было «на заказе нет кнопки».

  умолчанию. На `/ru` все плитки ведут на `/ru/…`, «сменить город» с
