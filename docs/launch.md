# Как выложить сайт apetit.md — пошагово

Для Амяна. Простыми словами, по порядку. Каждый шаг можно делать отдельно,
между шагами можно уйти и вернуться. В конце — как всё откатить, если
что-то пойдёт не так.

Перед началом и после каждого шага можно проверить себя одной командой:

```
npm run launch:check
```

Она ничего не меняет — только смотрит и печатает список «сделано / не
сделано». Ключи и пароли она не показывает никогда, только имена.

---

## Что уже готово

- Сайт собирается для Cloudflare: `npm run build:cf`.
- Его можно запустить у себя и посмотреть: `npm run preview:cf`, потом
  открыть `http://127.0.0.1:8787`. Аккаунт Cloudflare для этого не нужен.
- Автопроверки на этой сборке: `npm run test:e2e:cf`.

## Что нужно от вас

Три аккаунта (все бесплатные, кроме домена, который уже куплен):

1. **Cloudflare** — где будет жить сайт.
2. **Supabase** — уже есть, база заказов.
3. **host.md** — уже есть, там куплен домен apetit.md.

Плюс бот **@apetit_comenzi_bot** — уже есть.

---

## Шаг 1. База: применить две миграции

Это две минуты и делается до всего остального.

1. Зайдите в Supabase → ваш проект → слева **SQL Editor**.
2. Откройте файл `supabase/migrations/0005_test_orders.sql`, скопируйте всё
   содержимое, вставьте в окно и нажмите **Run**.
3. То же самое с `supabase/migrations/0006_place_order_is_test.sql`.

Что это даёт: заказы, которые оставляют автопроверки, перестают быть похожи
на настоящие. До этого они видны напоминаниям как обычные заказы.

Повторный запуск безопасен: если уже нажимали — ничего не сломается.

**Проверить:** `npm run launch:check`, раздел 3 — обе строки должны стать ✔.

---

## Шаг 2. Cloudflare: завести сайт

1. Зарегистрируйтесь на **cloudflare.com** (бесплатный план).
2. В терминале, в папке проекта:

   ```
   npx wrangler login
   ```

   Откроется браузер, нажмите **Allow**. Это вход один раз, дальше он
   помнится.

3. Выложить сайт:

   ```
   npm run deploy:cf
   ```

   Команда соберёт сайт и зальёт его. В конце она напечатает адрес вида
   `https://apetit.<ваше-имя>.workers.dev` — по нему сайт уже открывается.
   Это временный адрес, настоящий домен подключим на шаге 4.

**Проверить:** откройте напечатанный адрес с телефона. Должен открыться
экран городов. Заказ пока не оформляйте — ключей на сервере ещё нет.

---

## Шаг 3. Cloudflare: положить ключи

Ключи (Supabase, бот, секреты) **не лежат в коде и не должны туда попадать**.
На Cloudflare они кладутся отдельно, по одному. Для каждого выполните:

```
npx wrangler secret put ИМЯ
```

Команда спросит значение — вставьте его из вашего файла `.env.local` и
нажмите Enter. Значение нигде не показывается.

Список имён (ровно восемь):

```
NEXT_PUBLIC_SUPABASE_URL
NEXT_PUBLIC_SUPABASE_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY
ORDER_HASH_SECRET
TELEGRAM_BOT_TOKEN
TELEGRAM_WEBHOOK_SECRET
REMINDERS_SECRET
SITE_URL
```

`SITE_URL` — это `https://apetit.md`, без косой черты в конце.

После того как все восемь заведены, выложите сайт заново, чтобы он их
увидел:

```
npm run deploy:cf
```

**Проверить:** на временном адресе откройте меню и попробуйте оформить
заказ на **свой** телефон. Должна прийти карточка в Telegram.

---

## Шаг 4. Домен: host.md и Cloudflare

Домен apetit.md куплен в host.md. Чтобы он показывал наш сайт, у Cloudflare
должно появиться право им управлять.

1. В Cloudflare: **Add a site** → введите `apetit.md` → выберите **Free**.
2. Cloudflare покажет **два адреса серверов имён** (Nameservers), вроде
   `ada.ns.cloudflare.com` и `rob.ns.cloudflare.com`. Перепишите их.
3. Зайдите в личный кабинет **host.md** → ваш домен `apetit.md` → раздел
   **DNS / Nameservere / Servere de nume** → замените там серверы имён на
   те два, что дал Cloudflare → сохраните.
4. Вернитесь в Cloudflare и нажмите **Check nameservers**.

Дальше нужно подождать. Обычно полчаса-час, иногда до суток. Cloudflare
пришлёт письмо «Your site is active».

5. Когда домен активен, в Cloudflare: **Workers & Pages** → ваш Worker
   `apetit` → **Settings** → **Domains & Routes** → **Add** → **Custom
   domain** → `apetit.md`. Повторите для `www.apetit.md`, если хотите,
   чтобы работал и такой адрес.

Сертификат HTTPS Cloudflare сделает сам, отдельно ничего покупать не надо.

**Проверить:** откройте `https://apetit.md` — должен открыться сайт, и в
адресной строке должен быть замок.

---

## Шаг 5. Напоминания кассирам

Сайт умеет напоминать кассиру про непринятый заказ. Будильник для этого
живёт в базе: раз в минуту она стучится на сайт. Пока не сказано, куда
стучаться, напоминания не работают вовсе.

1. Supabase → **SQL Editor**.
2. Вставьте и выполните (вместо `ВАШ_СЕКРЕТ` — значение `REMINDERS_SECRET`
   из вашего `.env.local`, то же самое, что вы клали на шаге 3):

   ```sql
   insert into public.settings (key, value)
   values ('telegram_reminders', jsonb_build_object(
     'url', 'https://apetit.md/api/telegram/reminders',
     'secret', 'ВАШ_СЕКРЕТ'
   ))
   on conflict (key) do update set value = excluded.value;
   ```

**Проверить:** `npm run launch:check`, раздел 4 — три строки должны стать ✔.

---

## Шаг 6. Бот: направить заказы на боевой сайт

Пока бот не знает адреса сайта, кнопки в Telegram («Am primit») работать не
будут.

```
npm run telegram:setup
```

Команда сама возьмёт `SITE_URL` и секрет из `.env.local` и скажет боту, куда
слать события. В ответ напечатает адрес — он должен быть
`https://apetit.md/api/telegram/webhook`.

**Проверить:** `npm run launch:check`, раздел 5 — все строки ✔.

## Шаг 7. Телефоны точек

Для каждой точки — инструкция кассиру: `docs/telefon-punct.md`. Коды для
подключения лежат в базе, таблица `telegram_codes`.

## Шаг 8. Проверка скорости

Перед тем как рассказывать людям про сайт, проверьте скорость на живом
адресе. Для каждой из трёх страниц:

```
npx lighthouse@13.4.1 https://apetit.md/soroca --preset=mobile --quiet --output=json --output-path=docs/qa/lighthouse/soroca.json
npx lighthouse@13.4.1 https://apetit.md/ --preset=mobile --quiet --output=json --output-path=docs/qa/lighthouse/acasa.json
npx lighthouse@13.4.1 https://apetit.md/contacte --preset=mobile --quiet --output=json --output-path=docs/qa/lighthouse/contacte.json
```

Цели (SPEC §9.5): скорость не ниже **85** на меню и **90** на остальных
страницах; доступность, лучшие практики и SEO — **100**.

**Проверить:** `npm run launch:check`, раздел 7 — все строки ✔.

## Шаг 9. Последняя проверка

```
npm run launch:check
```

Должно быть «Сделано N из N» и пустой список «не сделано».

## Что проверить руками перед тем, как звать людей

1. Открыть сайт с телефона по 4G (не по домашнему Wi-Fi).
2. Выбрать город, положить в корзину два блюда, оформить заказ на свой
   номер. Карточка пришла в Telegram точки.
3. Нажать в Telegram «✅ Am primit» — карточка должна измениться.
4. Не нажимать ничего и подождать: через пару минут должно прийти
   напоминание.
5. Открыть сайт по-русски (`https://apetit.md/ru`) — проверить, что всё
   на месте.
6. Позвонить по номеру из раздела «Контакты» — проверить, что он верный.

## Как откатить

**Сайт стал хуже после выкладки.** Cloudflare → Workers & Pages → `apetit`
→ вкладка **Deployments** → найдите предыдущую версию → **Rollback**. Это
занимает секунды и возвращает ровно то, что было.

**Домен ведёт не туда.** В host.md верните прежние серверы имён. Страница
вернётся на старое место, но не сразу: адреса серверов расходятся по
интернету до суток.

**Заказы приходят не туда или пришли лишние.** Снять webhook у бота:

```
node -e "process.loadEnvFile('.env.local'); fetch('https://api.telegram.org/bot' + process.env.TELEGRAM_BOT_TOKEN + '/deleteWebhook').then(r => r.json()).then(j => console.log(j))"
```

После этого сайт продолжает принимать заказы в базу, но в Telegram они не
уходят. Вернуть обратно — `npm run telegram:setup`.

**Напоминания сыплются.** Supabase → SQL Editor:

```sql
delete from public.settings where key = 'telegram_reminders';
```

Будильник замолчит, всё остальное продолжит работать.

**Миграции базы** (шаг 1) обратно не откатываются — и не нужно: они только
добавляют колонку и параметр со значением по умолчанию, ничего не удаляют и
ничего не ломают.

---

## Чего делать НЕ нужно

- Не класть ключи в файлы проекта. Только `.env.local` у себя и
  `wrangler secret put` на Cloudflare.
- Не присылать ключи в переписку — ни мне, ни кому-либо ещё.
- Не менять `wrangler.jsonc` и `open-next.config.ts` наугад: это настройки
  сервера, ошибка там роняет весь сайт.
