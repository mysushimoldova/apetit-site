## A05 Injection — внедрение кода в страницу

**Что смотрели.** `buildClosedScript(hours)` собирает строку JavaScript и
`CheckoutPage` выводит её в `<script>`.

**Путь данных.** `hours` берётся у первой точки города, точки — константа
`POINTS` в `src/data/points.ts`. Ни запрос, ни заголовок, ни хранилище
браузера в этот путь не входят: страница собирается заранее
(`generateStaticParams`), параметр маршрута — только slug города, и он
проверяется `isCitySlug` до обращения к точкам.

**Что попадает в текст скрипта.** Два числа (`08:30` → `510`, `23:00` →
`1380`) и две константы (`"Europe/Chisinau"`, `"data-closed"`) через
`JSON.stringify`. Строки часов в скрипт не переносятся вовсе — они
превращаются в числа функцией `toMinutes`.

**Второй рубеж.** Перед сборкой оба числа проверяются: целое, от 0 до 1439.
Не прошло — возвращается пустая строка, скрипта на странице нет. На это есть
тесты, включая часы `"</script><script>alert(1)</script>"`
(`src/lib/order/closed-script.test.ts`).

**Вывод:** внедрение недостижимо. Проверка добавлена как запас, а не потому,
что нашлась дыра.

**CSP.** Политика не расширялась: `script-src 'self' 'unsafe-inline'` стоял и
раньше (`src/lib/security-headers.ts`, там же написано почему). Экран городов
уже выводит такой же встроенный скрипт (`city-redirect-script.ts`) — приём для
проекта не новый.

## A01 Broken Access Control — может ли скрипт разрешить лишнее

Скрипт решает только, видно ли баннер. Приём заказа решает сервер
(`src/server/orders` → `placeOrder`), он же сверяет часы по своему времени и
отвечает `closed`. Подмена `data-closed` в инструментах разработчика или
переведённые назад часы телефона показ баннера уберут, но заказ вне часов
сервер всё равно не примет — тест на это уже был раньше («вне часов решает
сервер: у телефона часы врут — заказ не принят», `e2e/checkout.spec.ts`).

## A10 Отказ в неожиданной ситуации — закрыто ли по умолчанию

Скрипт целиком в `try/catch`. Если он не выполнится (отключён JS, старый
браузер, ошибка в `Intl`), признак не поставится, баннер не покажется — но и
кнопка «Trimite comanda» останется неактивной: она выключена, пока корзина не
подставилась (`disabled={closed || sending || !hydrated}`). То есть без
JavaScript заказ не уходит вовсе. Отказ закрытый.

## Радиус влияния

- `buildClosedScript` — один вызов (`src/routes/checkout.tsx`).
- `CLOSED_ATTRIBUTE` — два места: скрипт и эффект в `CheckoutView`.
- `Sheet` — три вызова: лист блюда, корзина, окно смены города. Работа с
  историей задевает все три.

Разобрано отдельно окно смены города: кнопка «назад» там делает то же, что
Esc, — `onCancel`, то есть `router.push` в город корзины. Шага назад мы при
этом не делаем (ушли на другой адрес — своя запись уже не наверху), так что
переход не отменяется.
