# Данные меню и страница меню — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Каталог меню в коде (типы + zod + данные из SPEC приложения А) и страница `/[city]` по DESIGN 2.1: шапка, чипы категорий, слово-вывеска, плитки блюд с фото. Только просмотр.

**Architecture:** Данные — `src/data/menu/` (zod-схемы → типы; категории, блюда, добавки, доступность по точкам; `getMenuForCity()` собирает категории с включёнными блюдами и ценами точки). Страница — серверный компонент, три клиентских островка: `CategoryChips` (IntersectionObserver + плавный скролл), `RevealGrid` (появление плиток при скролле), `HeaderCityButton` (сменить город). Фото — `next/image` с глобальным `loaderFile`, srcset из готовых 400/800/1600.

**Tech Stack:** Next.js 16 · React 19 · Tailwind 4 · zod 4 · lucide-react · Vitest · Playwright.

**Spec:** промпт архитектора 19.09.2026 («данные меню и страница меню»); SPEC §2, §3 шаг 2, §7, приложение А; DESIGN.md 2.1 → Header, Category Chips, Hand-drawn Icons, Category Billboard, Product Tile, Food Image, Price Pill, Add Button, Motion фаза 1, Layout; макеты `docs/mock-meniu-soroca-390.png`, `docs/mock-kebab-variante.png` (вариант A).

## Global Constraints

- Данные строго из SPEC приложения А; RU — черновой перевод с `// TODO ru: проверить`.
- Категории в порядке: Kebab, Menu, Burgers, Gözleme, Crispy, Hot Dog, Sandwich, Salad, Pizza, Sosuri, Drinks, Desert (+ Supe в конце, все супы выключены — категория без блюд не показывается).
- Slug блюда = имя файла фото. Нет фото → `photo: null` и плитка-заглушка Sand с рисованной тарелкой.
- Пицца выключена в `soroca-centru` и `soroca-noua`; супы выключены везде; остальное включено везде по базовой цене.
- Тексты интерфейса — только через `messages.ts`; нет текста → `[ТЕКСТ: …]`.
- Никаких box-shadow на плитках/чипах/шапке; фото — только «лужица». Радиусы 9999/12/16/24.
- Анимации: плитки y 12→0 + opacity один раз при появлении, задержка 40ms по колонкам; плавный скролл по чипу; reduced-motion → без анимации и без smooth.
- Корзина, лист блюда, оборот иконки, слой линий фона, `/ru/` маршруты — НЕ в этой задаче.

## Review Focus

1. Блюдо без фото (лимонады, кофе) не должно ломать сетку и next/image — заглушка. — Vitest (photo null допустим) + e2e «нет битых img».
2. Узкие фото (бутылки, только 400px) — srcset не должен ссылаться на несуществующие 800/1600. — unit-тест загрузчика.
3. Город Otaci — интерфейс на RU (чипы, «de la», «лей»), `lang="ru"`. — e2e.
4. Категория, в которой для точки нет включённых блюд, не рендерится (ни чипа, ни вывески). — Vitest `getMenuForCity` + e2e /soroca без PIZZA.
5. Чип-якорь при загрузке с `#burgers` в URL — секция не должна прятаться под sticky-шапкой (`scroll-margin-top`). — e2e клик по чипу проверяет положение секции.

## Grill-me — вопросы и принятые ответы

❓ **Q1 — Состав кебабов и бургеров:** SPEC даёт только общую базу («все кебабы содержат…»), макет показывает базу + отличительный ингредиент (cașcaval, crispy, vită). Что класть в данные?
➡️ База из SPEC + ингредиент из названия блюда, как в утверждённом макете (Kebab Cheese → cașcaval; Crispy → crispy; Philly Beef → vită, cașcaval; cheeseburger → cașcaval + pui / vită-porc / crispy). Помечено в PROGRESS.md на подтверждение.

❓ **Q2 — Цены соусов отдельно (меню 10/15 vs касса 8/10):** SPEC — УТОЧНИТЬ.
➡️ Ставим цены печатного меню (ketchup 10, maioneză 15): приложение А — «цены базовые» из меню. Вопрос в PROGRESS.md.

❓ **Q3 — «Sos Apetit (dulce / picant)»:** одно блюдо или два?
➡️ Одно блюдо с двумя вариантами по одной цене (15) — фото одно. «de la» не показывается, т.к. цены равны.

❓ **Q4 — «Apă plată / gazată»:** одна строка в SPEC, два фото.
➡️ Два блюда (`apa-plata`, `apa-gazata`) по 18 — у каждого своё фото.

❓ **Q5 — Названия сэндвичей/салатов/пицц:** в SPEC «Cu salam fiert-afumat», «Grecească», «Margarita».
➡️ Сэндвичи — «Sandwich cu salam fiert-afumat» / «Sandwich cu șuncă de găină» (заголовок таблицы + строка); салаты — «Salată Grecească» / «Salată Cezar»; пиццы и остальное — как в SPEC без префикса (под вывеской PIZZA «Margarita» читается). Вопрос в PROGRESS.md.

❓ **Q6 — Убираемые ингредиенты:** SPEC не перечисляет по блюдам.
➡️ `removable` = состав блюда без основы (lipie / chiflă / tortilla / ciabatta / bază pizza). Лист блюда — следующая задача, там уточним.

❓ **Q7 — Разрешённые добавки:** SPEC — предположение.
➡️ Ингредиентные добавки (carne, șuncă, salam, becon, ceapă, cașcaval, morcov, castraveți, соусы «в блюдо») — kebab, burgers, hot-dog, sandwich, gözleme; соусники — всем, кроме drinks/sosuri/desert. Как в SPEC 2.4 (предположение), вопрос в PROGRESS.md.

❓ **Q8 — RO/RU в шапке:** SPEC 7 — `/ru/soroca`; маршрута ещё нет.
➡️ Показываем переключатель статически (активный язык Ink, второй Smoke), без ссылок. Маршрут `/ru/[city]` — вопрос архитектору.

❓ **Q9 — Кнопка города в шапке:** только вид или действие?
➡️ Действие уже есть (`useChangeCity`): очистить выбор и вернуться на `/`. Подпись для скринридера — «Schimbă orașul» из DESIGN.md.

❓ **Q10 — Подпись кнопки «+» для скринридера:** текста нет.
➡️ «Adaugă» — слово из DESIGN.md (Primary «Adaugă · 198 lei»), RU «Добавить» (TODO ru).

❓ **Q11 — Заголовок страницы (title):** нужен текст.
➡️ Шаблон из SPEC 8: «Apetit Soroca — kebab, burgeri, comandă online»; RU черновик.

❓ **Q12 — Фото в тайле: `next/image` требует width/height:** откуда?
➡️ Из `images.json` (ширина/высота мастера) — сохраняем пропорции, высота 150px через CSS.

❓ **Q13 — Супы:** нет категории в списке архитектора.
➡️ Категория `supe` последней, все три блюда выключены везде → не рендерится нигде. Вопрос: продаются ли.
