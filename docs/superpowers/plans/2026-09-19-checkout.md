# Оформление заказа — план реализации

**Goal:** (1) убрать `secure-workflow-guide`, смягчить правило `insecure-defaults`;
(2) 4 правки корзины (база блюда, «Extra» / «Sos aparte», safe-area,
«Golește coșul»); (3) страница `/[city]/comanda` + подтверждение, сервер
`submitOrder()` без Telegram/Supabase.

**Spec:** промпт архитектора 19.09.2026 («чекаут»); SPEC §3 шаги 5–6, «Вне
рабочих часов», §8 (адреса), §9.3 (номер с 1001, цена на сервере), §9.4
(лимиты, honeypot); DESIGN.md → Point Card, Input, Primary/Secondary, Closed
Banner, Order Confirmation.

## Архитектура

- **Сервер — Server Action** (`src/app/[city]/comanda/actions.ts`, `"use server"`),
  тонкая: читает заголовки (IP с Cloudflare, тестовое время) и зовёт
  `submitOrder()` из `src/server/orders/` (`import "server-only"`). Почему не
  route handler: у Server Action Next 16 сам сверяет Origin с Host (защита от
  CSRF, docs/01-app/02-guides/data-security.md), аргумент — обычный объект,
  отдельный публичный адрес API не нужен. Всё проверяется zod заново.
- **`src/server/orders/`**: `schema.ts` (zod входа), `phone.ts` (нормализация
  +373), `hours.ts` (часы Europe/Chisinau — общий для клиента, без server-only),
  `limits.ts` (память процесса, `// TODO: перенести в Supabase`),
  `number.ts` (сквозной с 1001), `submit.ts` (`submitOrder(input, ctx)` —
  чистая, время/IP/хранилища приходят в `ctx`, тесты без сети).
- **Цена** — `priceLine()` из `src/lib/cart/pricing.ts` по каталогу выбранной
  точки (`buildPointCatalog(pointId)`), как и обещано в задаче корзины.
- **Страница** `/[city]/comanda` — серверная обёртка (город, точки, каталоги
  точек без фото), клиентская форма. Пустая корзина → `router.replace` в меню.
- **Подтверждение** — `/[city]/comanda/[nr]` (SPEC §8). Базы ещё нет: снимок
  ответа сервера кладётся в sessionStorage, страница читает его; нет снимка →
  в меню. Корзина очищается только после ответа `ok`.
- **Часы**: клиент — только показ (баннер, кнопка disabled, перепроверка раз в
  минуту), решает сервер.

## Решения («допрос»)

- Q: Что при honeypot? → Отказ с общим кодом `rejected`, заказ не пишется.
  Ботам не важно, человеку поле не видно (`display:none` + `tabindex=-1` +
  `autocomplete=off`).
- Q: Дубликат за 2 минуты? → Возвращаем тот же номер (человек дважды нажал —
  видит свой заказ, кассир получает один). Лимит 3/10 мин считает только
  новые заказы.
- Q: Лимит по IP (SPEC 9.4)? → Да, 10 заказов / 10 мин с IP, только когда IP
  известен из `cf-connecting-ip` (Cloudflare). `x-forwarded-for` подделывается —
  не доверяем. На Vercel (план B) — отдельная правка.
- Q: Тестовое время для e2e? → Заголовок `x-apetit-test-now` читается только
  при `APETIT_E2E=1` и не в production (`next build` всегда production).
- Q: Недоступное в точке блюдо на клиенте? → Не выкидываем молча, помечаем
  строку; сервер отвечает `unavailable` со списком — это и проверяет e2e.
- Q: Геолокация без координат точек? → Координат в SPEC нет (адреса
  УТОЧНИТЬ). Код расстояния есть и покрыт тестами; запрос разрешения
  — только если у точек города есть координаты. Сейчас не спрашивает.
- Q: Номер заказа? → SPEC 9.3: сквозной с 1001 (в памяти процесса до Supabase).
- Не делаем (нет в задаче): «Определить, где я», запоминание имени/телефона,
  маршрут `/ru/…`.
